# Rust packaging idioms

Source: [Fedora Rust Packaging Guidelines](https://docs.fedoraproject.org/en-US/packaging-guidelines/Rust/)
(cite this URL; § names below are its section headings). Local provider:
[cargo-rpm-macros.spec](../../../../specs/c/cargo-rpm-macros/cargo-rpm-macros.spec) (also provides the legacy
`rust-packaging` name). Check crate/feature providers in `specs/r/rust-*/*.spec`, including version-suffixed
compatibility packages (e.g. `rust-bitflags1`); provider versions must satisfy the requirement.

Two kinds of package:
- **Crate** (`rust-<crate>`, from crates.io via `%{crates_source}`): generated by `rust2rpm`; ships sources in
  `%{cargo_registry}` via `-devel`/`+feature-devel` subpackages; `%bcond check 0|1` MUST be set.
- **Non-crate project** (application, workspace): normal name (MUST NOT use `rust-` prefix), MUST NOT ship crate
  sources/`crate(...)` provides, SHOULD NOT use `%{crates_source}` or `%cargo_install` (copy from `target/rpm/`).

## Canonical shape (application, system crates)

```spec
BuildRequires:  cargo-rpm-macros >= 24

%prep
%autosetup -n foo-%{version} -p1
%cargo_prep

%generate_buildrequires
%cargo_generate_buildrequires                 # same -a/-n/-f flags as below

%build
%cargo_build                                  # same flags everywhere
%{cargo_license_summary}
%{cargo_license} > LICENSE.dependencies

%install
install -Dpm0755 target/rpm/foo -t %{buildroot}%{_bindir}

%check
%cargo_test

%files
%license LICENSE LICENSE.dependencies
%{_bindir}/foo
```

`License:` of the binary package = SPDX `AND` of the crate's license and the `%cargo_license_summary` output
(statically linked crates), typically recorded as a comment block above the tag.
Find live examples: `grep -l '%cargo_license_summary' specs/*/*/*.spec | head`.

## Anti-patterns

| Seen in spec / change | Fix | Level (§) |
| --- | --- | --- |
| `cargo build`/`cargo test` called directly | `%cargo_build` / `%cargo_test` (flags, offline registry) | MUST use macros in their scriptlets (RPM macros) |
| No `%generate_buildrequires` + `%cargo_generate_buildrequires`; manual `BuildRequires: crate(...)`/`rust-foo-devel` | Generated BRs (unless vendored) | MUST (Dynamically generated BuildRequires) |
| `-a`/`-n`/`-f FEAT` on some `%cargo_*` calls but not others | Pass identical flags to `%cargo_generate_buildrequires`, `%cargo_build`, `%cargo_test`, `%cargo_license*` | MUST for license macros; otherwise BRs/tests/licenses don't match the build (License tags, RPM macros) |
| `License:` = only the project's license for a binary | Include statically linked crate licenses (`%cargo_license_summary`) | MUST reflect linked code (License tags) |
| No `%cargo_license_summary`/`%cargo_license` after `%cargo_build` for binaries | Add them | MUST (RPM macros) |
| Vendored crates without need | Build against system crates | SHOULD NOT bundle (Vendored dependencies) |
| Vendored build still calling `%cargo_generate_buildrequires` | Drop it (`%cargo_prep -v vendor`) | MUST NOT (Using vendor tarballs) |
| Vendored build without `%cargo_vendor_manifest` + `%license cargo-vendor.txt` | Add both (generates `bundled(crate(...))` Provides) | MUST (Using vendor tarballs) |
| Vendored build shipping Rust crate sources or crate/feature development subpackages | Don't; C development interfaces (headers, linker files, `.pc` files) may still ship in `-devel` | MUST NOT (Using vendor tarballs) |
| Exact pins (`=x.y.z`) or bumped requirements patched into `Cargo.toml` | Relax bounds/port code; requirement MUST resolve in AZL (check matching crate/feature providers, including version-suffixed compatibility packages); report upstream | MUST be resolvable (Generic: dependencies) |
| git/`[patch]` crate sources | Patch to crates.io version; else bundle as path dep and declare `bundled(crate(...))` | SHOULD / MUST declare (Replacing git dependencies) |
| Tests skipped/filtered without comment | Comment with reason + upstream link | SHOULD (Running tests) |
| Crate: feature list edited without regenerating subpackages | Re-run `rust2rpm`; `+feature-devel` subpackages MUST match features | MUST (Subpackages for crate features) |
| Crate: `[profile.release]` overrides, unpackaged optional deps left in metadata | Patch them out (`rust2rpm -p`) | MUST / SHOULD (rust2rpm) |

## Overlay / change hazards

- **`%rhel` selects the vendored path.** Most Fedora Rust app specs with a vendor tarball gate it on
  `%if 0%{?rhel}` (rust-toolset BR, `-a1`, `%cargo_prep -v vendor`, `%cargo_vendor_manifest`). Defining `rhel`
  for a component (build define or `.azl.macros`) silently switches it to bundled crates: AZL crate security
  updates stop applying, `License:` must then cover every vendored crate, and every other `%rhel` branch in the
  spec flips too. Prefer the system-crate path; if vendoring is truly needed, make it explicit and justified.
- **Feature flags** added via overlay to one macro line only (e.g. `%cargo_build -f x`) desynchronise BRs, tests
  and the license list. Change all `%cargo_*` call sites together.
- **Cargo.toml dependency edits** must resolve against what AZL ships (system path) or against the vendor tarball
  contents (vendored path: regenerate the tarball; an edited requirement the tarball can't satisfy fails offline).
- **Removing `%check`/`%cargo_test`** to fix a build hides real breakage; filter specific tests with a comment.
